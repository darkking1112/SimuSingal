# 模型训练工作台

桌面「模型训练」页包含「数据标注」「训练配置」「实验与日志」。训练在外部 Python
进程中运行，GUI 不导入 PyTorch。

硬件选型与各任务的训练耗时参考见[训练硬件与时间参考](训练硬件与时间参考.md)
（含本机 CPU 实测锚点与按显卡档位的外推估算）。

## 手工标注

1. 在「信号导入」页把录制加入文件清单并导入，或用「IQ 信号生成」创建资产
   （「单个信号生成」单条合成；「信号集合生成」批量生成并自动标注）。
2. 在训练配置中选择新建图像边长，然后到「数据标注」点击「新建标注集」。默认 1024。
3. 在左侧选择资产，点击「添加左侧选中 IQ 资产」。后台将每个资产转换为一张时频图。
4. 点击「新增信号框」，拖动框移动、拖动角点缩放；点击框后可删除。
   横轴为时间，纵轴向下频率递减，顶部为最高频率。
5. 选择训练集或验证集，保存标注。无信号数据点击「标记无信号」后保存。
   未确认样本会阻止训练，避免被误当作负样本。
6. 至少准备一个训练样本和一个验证样本；正式训练需要更多独立录制样本。

第一版固定单类 `emitter`，新建数据集采用会话级标签。可打开生成器或 TorchSig
转换的检测数据集修正标签；已有逐跳数据集会保留其标签语义。
同一资产不能重复添加，同源窗口应放在同一划分，避免数据泄漏。

修改保存到 `annotations.json`，原始 `samples.jsonl` 保留。切换样本或正常关闭窗口时
保存尚未保存的编辑。训练启动后复制图像和合并后的标签作为本次快照，后续标注不会影响本次实验。

## 配置训练环境

页面中选择包含 `training/desktop_worker.py` 的源码根目录和训练 Python 解释器。
冻结应用不能把自身当作 Python；需选择独立环境。训练源码不随 wheel 交付。

```bash
python3 -m venv .venv-training
.venv-training/bin/python -m pip install -e '.[train,ml]'
# YOLO26s 开发对照需要：
.venv-training/bin/python -m pip install ultralytics
```

环境是否齐备可先用仓库自带脚本自检与补装（用**训练环境的解释器**运行，
Windows 把 `.venv-training/bin/python` 换成 `.venv-training\Scripts\python.exe`）：

```bash
.venv-training/bin/python scripts/check_training_env.py            # 只检查，并打印工作台填写指引
.venv-training/bin/python scripts/check_training_env.py --install  # 补装缺失的、可自动安装的项
```

脚本按组件列出 torch / onnx / onnxruntime / ultralytics（YOLO26s）/ RT-DETR 依赖 /
torchsig 的状态与版本，检查训练源码完整性与 CUDA 可用性，并给出「训练源码根目录 /
训练环境 Python」等字段应填的内容；带 `--rtdetr <目录> --rtdetr-config <YAML>` 时
顺带校验 RT-DETR 的两个路径字段。torch 与 torchvision 不会被自动安装（需按
CPU / CUDA 选择版本，脚本只给出命令）。

### 检测模型

- **YOLO26s**：选择本地初始权重，或留空使用 `yolo26s.pt`（首次可能下载）。
  复用 Ultralytics 训练器，关闭翻转、旋转、拼图等破坏时频图含义的增强。
  按已授权的开发对照策略自动传递放行参数，清单保持 `distributable: false`。
- **RT-DETR**：选择官方 [lyuwenyu/RT-DETR](https://github.com/lyuwenyu/RT-DETR)
  的 `rtdetrv2_pytorch` 目录和具体模型 YAML，例如
  `configs/rtdetrv2/rtdetrv2_r18vd_120e_coco.yml`。安装该实现需要的
  PyYAML、scipy、faster-coco-eval、pycocotools、tensorboard 等依赖。
  可指定初始 `.pth`。入口生成本次实验专属 YAML，配置数据、单类字典、尺寸、轮数、
  批大小及学习率；其他策略仍由原 YAML 决定，包括骨干预训练权重下载。
  当前桥不支持 Paddle 或 PyTorch v1。

### IQ 分类

选择 CNN / TCN。数据来源只有两种：**使用所选集合**（先在生成页把数据生成/导入为集合，
再点“导出训练数据…”得到 `iq_dataset.json` / `iq_dataset.npz`；仅已确认的 A09 类别进入训练）
与**已有数据集**（直接指定 `iq_dataset.json` / `iq_dataset.npz` 所在目录）。
TorchSig 混入数据集是训练脚本 CLI 的能力（`build_iq_dataset.py --torchsig-bundle --torchsig-map`），
页面不再暴露；页面上没有任何生成入口。CUDA 可用性在所选 Python 环境中检查。

### 生成数据

生成功能全部在 **「IQ 信号生成」页的“信号集合生成”子页**（表单 + 配置弹框），训练页不生成任何数据：

- **参数**：数量、种子、引擎（项目 / TorchSig）、目标集合（新建或追加）；信号与采样明细在“配置…”弹框里
  （每条的信号数范围、调制多选与类别均衡、SNR 范围、带宽占比、功率、采样率、时长、跳速）；
- **自动标注**：AMC = 调制方式；检测 = 起止时间（采样点）、中心频率、带宽、SNR，
  默认逐跳（跳频样式同时写会话与逐跳目标）；检测框在构建数据版本时才计算；
- **可复现**：配方（`gen_recipe_v1`）是内部不可变 JSON，生成时自动存入集合并绑定；
  同配方 + 同种子逐位复现（逐信号种子由样本序号派生）；高级里可导入/导出 JSON 与设置 TorchSig 环境；
- **执行**：项目引擎是主程序内的后台任务（纯 NumPy、带进度与取消；失败的一条只计数不静默改参数）；
  TorchSig 只能在 Linux 下生成（外部进程 bundle → 导入），Windows 上直接提示，
  但“导入 TorchSig bundle…”任何平台都能用；
- **产物**：分片资产 + 目标参考参数 + 初始标注（检测/AMC 标注集自动建立，来源 `generator`）。

`.[train]` 已包含固定版本 TorchSig 2.2.0；只需要数据生成时也可安装 `.[torchsig]`。
已有 bundle 的导入不需要安装 TorchSig（纯 NumPy 读端）。
建议先小规模生成，空间与机时需求取决于实际规模：bundle 导入时信号实例几何不合法的
记录/实例会被跳过并按原因计数（结果面板与任务状态栏可见，条数可能少于请求）。

### 数据版本与清单

训练与评估只读 `ready` 的数据版本（`dataset_versions`）：构建时选定任务标注集，固定每个目标的当前标签版本号、划分与预处理，之后的重新标注不影响已建版本与已启动实验。

- 清单契约 `dataset_manifest_v1`，流式写入并在校验后置 `ready`；每行一个训练样本，含 `sample_id, asset_id, asset_sha256, origin_group_id, target_id, label_revision_id, 提取范围, split`。
- **划分按 `origin_group_id` 分组**：同一次采集或同一生成场景不会跨训练/验证/测试；分组内再分层保证类别比例，配方的 `holdout` 优先于随机划分。
- 检测任务只纳入 `coverage=complete` 的录制；未标注目标整条排除并在数据版本卡片记录原因；另有无目标负样本行。AMC 每行为一个目标提取窗口。
- 预处理（`nfft`、图像尺寸、动态范围、IQ 窗口长度）写入数据版本，推理时用同一份实现。
- 资产数、目标数、训练样本数分别统计；训练页“使用所选集合”会先构建数据版本再按清单导出数据集（检测 → `AnnotationDataset`、AMC → `iq_dataset`），训练脚本直接消费两种目录格式；清单本身的直接接线仍待实现（`datasets.read_manifest` 已提供读取接口）。

### 生成参数 `gen_recipe_v1`（内部格式）

配方是不可变 JSON（界面上是表单，JSON 导入导出在“高级”里）：分布写法统一为 `fixed / choice(+weights) / uniform / loguniform / balanced`；用到生成器尚未支持的项时启动前直接报错，不静默忽略。

- **样本级种子**：第 i 个样本的种子由 `base_seed` 与 `i` 派生，样本独立可复现，支持断点续跑与并行（与顺序随机流生成的结果不逐位相同）；逐信号槽位再加盐 `sample_seed(base, i, k)`，同一条录制里的多个信号互不相同。
- **分层与留出**：`stratify` 要求每个格子至少有 `min_per_cell` 个样本，不足时预览报告（生成暂不补抽）；`holdout` 把指定参数范围的样本只分配到测试集（例如高 SNR 段、未见过的带宽段）。
- **参数预览**：生成前先做“仅抽参数、不合成 IQ”的试抽样（例如 1 万组），界面展示各参数分布与分层格子计数。
- **当前状态**：校验、样本级种子、预览、表单与执行器均已实现（生成时自动入库并绑定集合）；覆盖度回写 `coverage_cache` 与分层补抽属于后续。

### 生成器扩展与损伤（待实现）

| 能力 | 层级 | 主要参数 | 对真值与标签的影响 |
| --- | --- | --- | --- |
| 频偏 | 单信号 | 相对频偏或 Hz | 实际占用中心随频偏平移；`center_hz` 取实测值，`nominal_center_hz` 保持名义值 |
| 相位噪声 | 单信号（发射端） | 档位或噪声谱参数 | 不改变占用频带，只影响星座质量；参数写入生成摘要 |
| IQ 不平衡 | 记录级（接收端） | 幅度不平衡 dB、相位偏差 deg | 在 $-f$ 处产生镜像；镜像不标为目标，评估中记录镜像存在的样本 |
| 多径 | 单信号或记录级信道 | 径数、时延扩展、功率分布、衰落类型 | 功率与频谱形状改变，带内 SNR 与占用带宽按实测重算 |
| 独立符号率 | 单信号（数字样式） | `symbol_rate_baud` | 带宽与符号率、滚降需一致，不一致直接报错 |

约定：默认全部关闭且关闭时输出逐位不变（走数值等价回归）；施加顺序固定（基带成形 → 频偏 → 相位噪声 → 多径 → 叠加噪声 → IQ 不平衡）并写入摘要；每项损伤设上限，组合后占用频带必须仍在采样带宽内。

**当前状态**：五项全部未实现；接口在 `src/signal_analysis/impairments.py` 预留——逐项声明参数形状、施加阶段（逐信号 / 记录级）、顺序与对真值的影响；生成页“损伤”区按声明渲染并**置灰**，配方里用到未实现的项启动前报错（不静默忽略）。实现后把 `implemented` 改为 `True` 并补 `apply`，界面自动启用。

### TorchSig 数据接入

流程：`build_torchsig.py`（Linux/WSL/远程）→ bundle → 导入为分片资产；`components` 写入 `targets` / `target_versions`（`source=external`），类名经 `taxonomy.mapping_json` 映射到 AMC 类别，再加入集合与任务标注集。

- 多信号录制保留全部目标；AMC 训练按目标提取窗口，不再整条丢弃；未映射类名保留并统计。
- 时间轴用 `start_in_samples / duration_in_samples`（采样点），避免上游 `start/stop` 比例单位的坑。
- 标称 SNR 存 `params_json`，带内 SNR 用 `measure_band` 重测后写 `snr_db`（`inband_snr_v1`）。
- 当前状态：已实现（`torchsig_support.py`）。Linux 下可在生成页直接生成 bundle 后导入（外部进程，仅 Linux）；Windows 上直接提示只能 Linux，但可用“导入 TorchSig bundle…”选一个已生成的 `torchsig_bundle_v1` 目录；类别映射用显式 JSON（`{TorchSig 类名: A09 类别}`），未映射的保留并统计。

## 训练、评估、加载

点击「开始训练 → 导出 → 验收」。实验页显示阶段、日志、loss 和 IQ 验证准确率。
停止或正常关闭窗口会结束训练进程组；第一版不支持断点续训。重启后可查看历史日志和指标。

检测导出先做原生图与契约图的独立数值对账，再运行 `verify_onnx.py`。
这两个原生导出入口接收 RGB float32 `[0,1]`，工作台明确传递 `input_scale=1`，
不沿用通用适配器的历史默认缩放。

检测指标按保存的标注框计算：置信度 0.25、NMS IoU 0.5、匹配 IoU 0.5。
报告包括精确率、召回率、无信号样本误报率、CPU 推理与去重 P50/P95；延迟不包含 IQ 转图。
测试集不参与模型选择，训练结束后单独评估。这是二维框评分，不等同于生成器业务频段评分。

IQ 验证准确率和混淆矩阵使用数据集标签，不依赖资产 `generation`。
识别页面的当前资产真值评分仍受资产真值及类别映射限制，两者不会混用。
验收通过后点击「加载验收通过的模型」，清单会填入检测或识别页面。
验收通过只表示链路正确，不代表模型精度已达到应用要求。

## 常见问题

- **点击「开始训练」没有反应？** 启动前会逐项校验：训练源码根目录、训练 Python、
  检测数据集（或 IQ 数据配置）以及所选后端参数；校验失败时错误显示在「训练配置」
  页按钮下方的红字里（同时写入「实验与日志」页状态），只有通过校验才会创建
  `runs/<时间-id>/` 并切到实验页。最常见的拦截项：选了 RT-DETR 但未指定
  `rtdetrv2_pytorch` 目录与模型 YAML；训练数据集路径为空或无效（窗口重开后表单
  不保留上次选择，需重新选择）；已有任务尚未结束（等它完成或在实验页停止）。
- **TorchSig 数据每次一样吗？** 由生成页「种子」与请求条数决定：同配方、同种子逐位复现
  （逐信号种子由样本序号派生）；要换一批数据请改种子或参数。
- **标注页的框是自动的吗？** 从集合导出的数据集是自动的：检测框由目标参考参数经项目统一公式生成（检测页可直接查看/采纳），划分按 `origin_group_id` 整组；标注页仍可人工修正后保存。通过「添加左侧选中 IQ 资产」录入的样本没有
  自动标签，必须逐条确认（保存标注或「标记无信号」），否则训练会被拦截。
- **训练产物在哪里、怎么用？** 检测训练完成后的 `model/detector.onnx` 与
  `model/detector.json` 在实验目录中；「实验与日志」页选中该实验，点
  「加载验收通过的模型」即把清单填入「信号检测」页的 AI 检测入口（逐跳模型填入
  「跳频参数」页），随后选择数据资产点「AI 检测所选数据」即可。推理需要
  onnxruntime（`.[ml]`），未安装时 AI 入口自动禁用。
- **检测数据和调制识别的数据能共用吗？** 训练数据格式不同，不能直接互用：
  检测训练用 `tf_image_v1`（时频图 + 检测框，单类 `emitter`），调制识别训练用
  `iq_waveform_v1`（`(2,N)` 复基带窗口 + 类别标签）。同一批 **TorchSig bundle**
  可以两用：导入为集合后导出检测数据集，也可用训练脚本 CLI
  （`build_iq_dataset.py --torchsig-bundle --torchsig-map`，显式类别映射，未映射的类整条跳过）
  生成 IQ 分类数据集。本项目生成器两份数据建议分别生成（分布同源、样本独立）。
  推理端共享同一段 IQ：检测给出频带后，识别页「取用检测结果频带」可直接复用。

## 文件与当前边界

所有数据默认保存在工作区的 `training/datasets/` 和 `training/runs/<时间-id>/`。
每个实验保存 `experiment.json`、`environment.json`、`worker.log`、数据快照、
原生训练权重、`model/` 下的 ONNX/清单/指标，以及 `verification.json`。

- 标注器支持本项目时频图格式，不接受任意截图；不提供 IQ 调制类别人工编辑。
- 两个检测后端共用评估口径，尚无专门的多实验 A/B 汇总界面。
- TorchSig 2.2.0 的真实 CPU 生成验证在 Linux 环境进行；本机 Windows 上已验证
  bundle 导入（目标/标注/导出全链路）；CUDA 和最终冻结发行包需在目标环境另行验收。
- 冻结构建排除 torch、torchvision、ultralytics、torchsig；冻结应用或
  `SIMUSIGNAL_RELEASE=1` 时隐藏 YOLO26s 入口。训练源码、权重和实验目录不随 wheel 交付。
