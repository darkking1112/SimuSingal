## 1. 目标

1. 新增 `ai_model` 模型目录：**每个模型一个文件**，项目据此在「AMC 识别训练」页显示模型架构与参数；
2. 提供**统一的公共函数**（注册、构建、参数校验、导出包装），使 CLI、服务层校验、GUI 共用同一事实源；
3. 评估并接入 `custom/` 下的第三方模型（MCLDNN、PETCGDNN、CV_TRN、POET、AMC_Net、ASCS）；
4. 复用现有训练数据（`iq_dataset`），补"参数读取适配"（类别数、窗口长度、模型专用参数、输入布局）。

## 2. 四条设计红线

1. **`src/signal_analysis` 导入时永不加载 torch**：冻结桌面应用明确 `exclude: ["torch", ...]`（[packaging/projects.json](../../../packaging/projects.json)），且 `training/` 不随包分发，GUI 进程必须只读元数据。
2. **torch 实现不随 wheel 分发**：模型网络定义留在 `training/`（沿用"训练实现不随 wheel 分发，需要 `.[train]`"的既有约定）。
3. **ONNX 契约恒定**：对外输入永远是 `iq (1,2,N)` float32、输出 `scores (1,C)` 概率、softmax 写进导出图、batch=1 探测、`2e-4` 容差（现有自检见 [training/iq_cnn.py:249](../../../training/iq_cnn.py)）；模型内侧的布局转换必须发生在**导出图内部**。
4. **训练前向与导出包装共用同一个布局适配函数**，杜绝"训练-推理口径分叉"。

## 4. 目录与职责（混合布局）

```
src/signal_analysis/algorithms/amc/ai_model/     # 纯元数据，可随 wheel 分发；GUI/服务/CLI 共用（无 torch）
├── __init__.py      # SPECS 聚合；available_models() / model_spec(id) / describe(id) / validate_params()
├── base.py          # ModelSpec、ParamSpec 数据类；渲染（层表文本）与校验
├── cnn.py           # SPEC（id="cnn"，与现有 --arch 兼容）
├── tcn.py           # SPEC
├── mcldnn.py        # SPEC（阶段 3）
└── petcgdnn.py      # SPEC（阶段 3）

training/amc_models/                              # torch 实现，不随 wheel 分发
├── __init__.py      # 实现注册表：按 spec.implementation 解析模块；build_model()/export_onnx()
├── cnn.py, tcn.py   # 网络定义（从 training/iq_cnn.py 迁出）
├── _adapters.py     # AdaptedModel（内部布局转换，对外恒 (B,2,N)）+ SoftmaxWrapper
├── _compat.py       # trunc_normal_ / DropPath 等小工具（仅供训练目录内的维护副本使用）
├── _custom_loader.py# 按文件路径加载 custom/*.py（importlib，不改原文件，无需 __init__.py）
└── mcldnn.py 等     # 包装器：加载原模型 + 参数映射 + 布局声明（阶段 3/5/6）
```

**为什么是混合布局**（而不是全部放 `training/` 或全部放 `src/`）：

| 备选 | 结果 |
| --- | --- |
| 全部放 `training/amc_models/` + GUI 扫目录 | 冻结应用不打包 `training/`、GUI 无 torch，扫目录只能拿到文件名；要拿参数就得 AST 解析或跨界 import，脆弱 |
| 全部放 `src/`（含 torch 网络定义） | 违反"训练实现不随 wheel 分发"的既有约定；且一旦某文件模块级 import torch，GUI 直接打不开 |
| **混合（本方案）** | spec 是 UI 与服务层要展示的数据，合理随包；torch 实现留在训练侧；两者由测试保证一致 |

文件名约定：`spec.implementation == "amc_models.<file>"`，即**模型 ID = 实现文件名 = `--arch` 取值 = 实验记录里的 `arch`**；由测试强制一一对应（见 §8）。

**发现方式（显式聚合，不做运行时目录扫描）**：`SPECS` 由 `__init__.py` 手工聚合并保持顺序稳定。新增模型 = 新增两个文件（`src/.../ai_model/<id>.py` 与 `training/amc_models/<id>.py`），不依赖任何扫描逻辑。仓库测试强制三件事：spec ↔ 实现文件一一对应（无孤儿、无缺失）、`id` 不重复、`implementation` 与文件名一致。

**版本一致性（桌面应用 vs 训练源码目录）**：GUI 可选择另一份「训练源码根目录」，随应用分发的 spec 可能与该目录的实现不一致。规则：

1. `catalog_version`（目录级整数）与每模型 `model_revision`（结构或前向语义变更时 +1）都写进 `__init__.py` 导出的 catalog；
2. 训练侧永远从**自己那棵树**解析 spec + 实现（`train_iq.py` 把 repo `src` 提前插入 `sys.path`），启动时自查一致性；
3. GUI 的模型列表/参数表单：选定训练源码目录后，用训练 Python 运行**元数据查询接口**取其 JSON 作为展示依据——
   `python -c "import sys; sys.path.insert(0, '<repo>/src'); from signal_analysis.algorithms.amc.ai_model import catalog_json; print(catalog_json())"`；
   查询失败则回退为"应用内置目录 + 未验证"标记；
4. 起任务前做版本握手：GUI 把查询到的 `catalog_version` 写进配置，worker 侧比对自身目录版本，不一致直接拒绝并提示刷新模型列表；
5. `catalog_version` 与各 `model_revision` 记入 `experiment.json` 与清单 `training` 段，历史实验据此判定可比性。

## 5. 接口设计

### 5.1 `ModelSpec`（`src/.../ai_model/base.py`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | str | ✓ | 模型 ID；与 `--arch`、实验记录、清单 `training.arch` 共用；现有 `cnn`、`tcn` 不变 |
| `model_revision` | int | ✓ | 结构/前向语义版本；结构或行为变更时 +1（TCN 修正置 2），记入实验记录用于判定历史可比性 |
| `title` | str | ✓ | 页面显示名，如 "IQCNN（步长卷积）" |
| `summary` | str | ✓ | 一句话定位 |
| `implementation` | str | ✓ | 训练侧模块路径，如 `"amc_models.cnn"` |
| `layers` | tuple[str, ...] | ✓ | 架构展示行（层表文本；GUI 只读展示） |
| `params` | tuple[ParamSpec, ...] | | 参数 schema（默认值唯一事实源） |
| `samples` | str | ✓ | `"any"` / `"exact:128"` / `"min:256"`；训练前与数据集卡 `contract.samples` 比对，不符即失败 |
| `input_layout` | str | ✓ | 模型内部的偏好布局：`"iq_channels_first_v1"`（默认）或 `"iq_channels_last_v1"`（工厂内部转置）。调用方无需关心——工厂返回的模型统一接收 `(B,2,N)`（见 §5.3） |
| `requires` | tuple[str, ...] | ✓ | `("torch",)` 或 `("torch","timm")`；用于预检与实验记录 |
| `exportable` | bool | ✓ | 是否允许进入产品推理链路；为 `False` 的模型在页面**置为不可选**（阶段 6 若停留在离线实验则另立模式，见 §7 阶段 5/6） |
| `notes` | str | | 资源提示，如"CPU 上 1024 点训练耗时高" |

### 5.2 `ParamSpec` 与参数规则

| 字段 | 说明 |
| --- | --- |
| `name` | 参数名，等于实现 `build(params=...)` 的键名 |
| `kind` | `int` / `float` / `int-list` / `bool` / `choice` |
| `default` | 默认值（唯一事实源；实现模块不得再写一套） |
| `minimum` / `maximum` | 数值约束，带 `exclusive_minimum` / `exclusive_maximum` 开闭区间标志（如 dropout 的 `[0,1)`） |
| `element_minimum` / `element_maximum` / `element_odd` | 列表元素级约束（如 cnn 通道数 ≥1、核长为不小于 3 的奇数） |
| `length` | 列表长度约束（exact/min/max；如 cnn 恰好 3 个通道、tcn 给 1～3 个只用第 1 个） |
| `divisible_by` / `divisor_of` | 整除类约束（如注意力头数整除隐藏维度） |
| `choices` | `choice` 用 |
| `help` | GUI tooltip 与 CLI 帮助共用 |

**模型级交叉校验**：spec 另提供**纯 Python** 的 `validate(params) -> dict`（处理跨字段规则，如 `d_model % n_head == 0`），GUI 与训练侧共用同一函数。

规则：

- **未知参数一律拒绝**（不是忽略），错误信息列出可用参数名；
- **网络结构参数与公共训练配置分离**：`channels/kernel/dropout/heads/...` 属模型参数，走 `--model-params`；`lr/weight_decay/patience/epochs/scheduler/monitor` 属公共训练配置，沿用现有字段；
- **旧 CLI 参数与 `--model-params` 冲突处理**：同一参数被两处显式给出时报错（不静默取其一）；旧 flag 的 argparse 默认值改为"未提供"（`None`/`SUPPRESS`），避免默认值覆盖模型自己的默认值；映射只对声明了该参数的模型生效；
- **与现状的等价关系（阶段 1 验收）**：`cnn` 的规则与现有 `iq_tuning_args` 逐条等价（3 个通道、不小于 3 的奇数核长、`[0,1)` dropout）；
- **一处有意的行为修正**：`tcn` 核长校验改为与实现一致（`kernel >= 2`）。实测现状是服务层放行 `kernel=1`、模型构造时才失败，本次收敛并记录到变更说明（`iq_tuning_args` 现有测试中对应断言需同步更新）。

### 5.3 实现注册表（`training/amc_models/__init__.py`）

```python
def build_model(name: str, *, classes: int, samples: int, params: dict | None = None,
                torch_module=None) -> nn.Module      # 统一契约：输入 (B,2,N)、输出 (B,C) logits
def export_onnx(model, path, *, spec, classes, samples, opset=17) -> Path
def load_state(model, path) -> None                  # 阶段 4（checkpoint）后启用
```

规则：

- **`build_model` 返回的模型永远直接接收 `(B,2,N)`、输出 logits**：布局转换在工厂内部包装一次（`AdaptedModel(raw, spec.input_layout)`）；**训练、验证评分（[train_iq.py:236](../../../training/train_iq.py) 的 `predict`）、导出、GUI 预检用的是同一个对象**，不存在"只改训练循环、漏改评分"的可能；
- 导出只在最外层追加 softmax（`SoftmaxWrapper(adapted)`）；布局转换已在模型内部，导出图对外形状恒为 `(1,2,N)`；
- 校验顺序：`spec.samples` 与数据集 `samples` 一致性 → `requires` 依赖检查（`importlib.util.find_spec`，**在 import 实现之前**）→ 参数校验（含未知键拒绝与模型级 `validate`）→ 调用实现模块的 `build(*, num_classes, samples, params)`；
- 实现模块只写网络本体：不写布局转换、不写 softmax、不写默认值。

**依赖不可用的模型**：仍出现在目录与页面上（按 `requires` 标注不可用原因），但 `build_model` 直接给出可执行提示；**不允许**用 `sys.modules` 伪注入的方式"伪造"依赖。

### 5.5 兼容性薄壳

`training/iq_cnn.py` 保留为**转发层**，继续导出旧名字：`IQCNN`、`IQTCN`、`ARCHITECTURES`、`INPUT_NAME`、`OUTPUT_NAME`、`TOLERANCE`、`DEFAULT_*`、`build_model`、`SoftmaxClassifier`、`train_classifier`、`export_onnx`。这样 `train_iq.py` 与三处文档引用可以分批迁移。

注意口径：**"行为不变"指运行行为（argv 序列、模型数值、产物结构），不等于测试文件一行不改**——涉及注册表、导入结构与报错文案的现有断言需要随新结构同步调整（典型如 [test_iq_training_tools.py:415](../../../tests/analysis/test_iq_training_tools.py) 的"模块级 import torch 例外"规则、[test_iq_training_tools.py:479](../../../tests/analysis/test_iq_training_tools.py) 的 `build_model` 用例）。

## 7. 命令级验收细则

### 阶段 0（TCN 修正）

1. **结构回归**（新增测试，必须"失败于现状、通过于修复"）。注意：模型默认训练态，`classifier` 里的 `Dropout(0.1)` 会让两次前向天然不同，直接比较输出会**误通过**（已实测），必须 `eval()` + `no_grad()`：

   ```python
   model = build_model("tcn", 3).eval(); x = torch.randn(2, 2, 256)
   with torch.no_grad():
       before = model(x)
       next(model.blocks.parameters()).data.add_(1.0)
       assert not torch.allclose(before, model(x))   # 修复后必须不同；现状相同 → 断言失败
   ```

   另补**梯度检查**（训练态、单次 `backward`）：`blocks` 的 40 个参数应全部获得非零梯度（现状实测 0/40）。

2. `python -m pytest tests/analysis/test_iq_training_tools.py -q` 全绿（含上述新测试）。
3. 冒烟重训并更新 **TCN 相关**数字：`.venv/bin/python training/train_iq.py --data training/data/iq --arch tcn --epochs 30`（其余沿用 §5 冒烟规模），把新数字替换进 [调制识别_AI特征学习.md](调制识别_AI特征学习.md) §5/§1.2，并注明"TCN 修正前数字作废"；**文档中已有的 CNN 成绩无需随本次修正替换**。
4. 确认 CNN 路径不受影响：同种子重跑 `--arch cnn`，`metrics.json` 与修正前一致。
5. `tcn` 的 `model_revision` 递增并写入后续实验记录；历史实验按 `model_revision` 区分口径，保留独立变更记录。

### 阶段 1（契约、注册表与接口）

1. `python -m pytest tests/analysis -q` 全绿。**允许按新结构同步调整涉及注册表、导入结构与报错文案的断言**（如 [test_iq_training_tools.py:415](../../../tests/analysis/test_iq_training_tools.py) 的 torch 例外规则、`build_model` 用例）；`tests/analysis/test_numeric_modules.py` 的"不得加载 torch"子进程检查必须保持通过。
2. **GUI 安全导入**（新增测试）：子进程 `import signal_analysis.algorithms.amc.ai_model` 后断言 `torch`、`onnxruntime` 不在 `sys.modules`。
3. **注册表与目录一致性**（新增测试）：spec ↔ 实现一一对应、无孤儿、`id` 不重复、`implementation` 与文件名一致；`ParamSpec.default` 落在约束内；`catalog_version`、`model_revision` 已声明。
4. **参数规则**（新增测试）：未知键拒绝；奇数核长/列表长度/开区间/整除规则生效；旧 flag 与 `--model-params` 冲突报错；tcn `kernel=1` 被拒（与实现一致）。
5. **行为对比基线 = 阶段 0 修正后**：同数据集、同种子、CPU 重跑 `--arch cnn/--arch tcn --epochs 3`，与**阶段 0 产物**对比 `history` 与 `best_accuracy` 完全一致；`verify_iq.py` 十项检查通过。
6. **服务层等价**：`iq_plan` 生成的 argv 序列与现状一致（tcn 核长规则例外，见 §5.2）。
7. `train_iq.py --help` 在不装 torch 的环境可运行（沿用现有测试口径）。

### 阶段 2（展示、参数界面与窗口配置）

1. `python -m pytest tests/analysis/test_training_page_split.py tests/analysis/test_training_workbench.py tests/analysis/test_models_gui.py -q` 全绿。
2. 页面手工检查：切换模型时层表、参数量、建议窗口、依赖与可用性状态同步刷新；"窗口长度"默认随所选模型变化。
3. 非法参数双侧拦截：GUI 提交前报错，worker 侧 `preflight` 复核同一规则（同一份 `validate_params`）。
4. **窗口长度闭环**：`spec.samples`、页面窗口配置、数据集卡 `contract.samples`、清单 `input.samples` 四者一致；长度非法时**不产生快照**（worker 预检先于数据处理）。
5. **catalog 查询与版本握手**：模型列表来自训练环境的元数据查询接口；`catalog_version` 与应用内置目录不一致时拒绝起任务并提示刷新；查询失败时回退"内置目录 + 未验证"标记。

### 阶段 3（MCLDNN / PETCGDNN）

1. 构建与导出：`build_model("mcldnn", classes=6, samples=1024)` 前向 `(2,2,1024) → (2,6)`；`export_onnx` 通过图内 softmax、batch=1、`2e-4` 容差自检。
2. 端到端：训练 → `verify_iq.py` 十项通过 → GUI「加载验收通过的模型」推理一次成功。
3. 记录：`metrics.json`/清单出现 `model_id、model_params、num_params、model_deps`；单 epoch 耗时写入实验记录。
4. 与 CNN 基线同划分对比并写进文档（注明"接口可行性验证，不代表最终精度"）。

### 阶段 4（训练策略：复现 `custom/训练参数.md`）

1. 默认路径：不传新参数时，`history`、早停轮数、最优轮与阶段 1 记录一致（新参数全部 opt-in）。
2. 勾选路径需完整覆盖文档口径：`ReduceLROnPlateau(monitor=val_loss, mode=min, factor=0.5, patience=5, min_lr=1e-7)`、早停 `val_loss` patience=10、最大 200 轮、**最优权重按最低 `val_loss` 判定并保存**。
3. **checkpoint 内容**：`model_id`、`model_revision`、最终结构参数（`params`）、类别顺序、窗口长度、版本与权重；`load_state` 做兼容性检查（ID/结构参数/窗口长度/类别顺序不一致即拒绝加载）。
4. **指标与输出**：`metrics.json`、CLI 输出支持"最佳验证损失"（现固定输出"最佳验证准确率"，需要扩展），并保留"最佳验证准确率"字段供旧口径比对。
5. `verify_iq.py` 与产品推理链路不受影响（清单与 ONNX 契约不变）。

### 阶段 5 / 6（复杂模型）

1. **依赖检查先于导入**：`preflight` 在 import 实现模块之前完成 `requires` 检查；缺依赖的模型仍显示在目录中并注明不可用原因（如"训练环境缺少 timm"），给出可执行提示（安装依赖，或改用训练目录内的维护副本），不堆栈崩溃；**不得**用 `sys.modules` 伪注入替代依赖。
2. 导出成功者：ONNX 概率和 ≈1、与 PyTorch 数值偏差 ≤ `2e-4`、eval 模式下无随机行为（CV_TRN 的 RPO、POET 的增广必须在 eval 关闭——显式验证；POET 的 `InstanceAGC` 属确定性计算，保留并验证训练/推理一致性）。
3. **`exportable=False` 的执行流程**：当前链路固定"训练 → 导出 → 验收"，布尔标记不足以让不可导出的模型正常训练。阶段 6 的做法：
   - 本批先把这类模型在页面**置为不可选**（`iq_plan` 直接拒绝并说明原因）；
   - 若要支持离线实验，另立明确模式：输出 checkpoint（无 ONNX/清单）、任务成功条件、**不进模型库**（无清单即不可加载）；
   - 若阶段 6 结束时仍停留在离线实验，阶段目标按**"部分完成"**记录，不宣称达成。
4. CV_TRN 的 `cls_token` 构造期按 CUDA 可用性写死设备的问题，统一交由 `.to(device)` 控制。

## 8. 风险与待决项

| # | 风险 / 待决 | 说明与建议 |
| --- | --- | --- |
| 1 | **TCN 修正改变行为** | 历史 TCN 实验记录不可再比较（按 `model_revision` 区分口径）；重建一次基线；文档只更新 TCN 相关数字，**CNN 成绩不动** |
| 2 | **窗口长度语义** | 现有 GUI 固定 1024 点、6 类；RML 系模型按 128 点设计。该 N 下符号数结构不同，精度需重新评估，不能沿用 0.91 那组成绩；窗口长度进入阶段 2，并在**快照之前**校验 |
| 3 | `timm` 取舍（二选一） | 只用到 `trunc_normal_`、`DropPath`，但 `_compat.py` **无法消除原文件顶部的 import**。① `[train]` 加 `timm`（并修 `timm.models.layers` 旧路径）；② 在训练目录维护一份改过导入、基于项目框架部分重构的副本（保留核心功能与模型语义，可顺带去掉无用分支）。**不采用** `sys.modules` 伪注入 |
| 4 | AMC_Net / ASCS 的复数算子 | 实数化改写 + 数值等价验证工作量不确定，可能长期停在"离线实验"；建议先明确"是否必须进产品"再排期；结论限定在"当前环境/导出器/opset 17" |
| 5 | 资源画像 | 1024 点下 MCLDNN 是长序列 LSTM、CV_TRN/POET 是 Transformer，GUI 默认 device=cpu；spec 需给出建议窗口与耗时提示 |
| 6 | 归一化与随机性 | POET 自带 `InstanceAGC`（确定性，保留并验证一致性）+ `PhysicsAwareAugmentation`（训练态随机，eval 关闭需显式验证）；CV_TRN 只有 RPO（训练态随机相位），**没有 AGC**。与本项目 `unit_rms` 契约的叠加效果要写进验收 |
| 7 | 参数默认值归属 | `ParamSpec.default` 是唯一事实源；实现模块不得再写一套默认值（由一致性测试约束） |
| 8 | 应用与训练源码的目录版本漂移 | 见 §4 版本一致性规则：训练环境元数据查询接口 + `catalog_version` 握手；不满足则拒绝起任务 |
| 9 | 离线实验的边界 | `exportable=False` 的模型走不完"训练→导出→验收"；若支持离线模式，需定义 checkpoint、成功条件与是否入库，并把对应阶段标注为部分完成 |
