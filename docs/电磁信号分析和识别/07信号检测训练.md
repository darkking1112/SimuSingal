# 信号检测训练

版本：0.1.0。更新日期：2026-10-03。

「信号检测训练」是信号分析桌面应用的第七个标签页，负责**检测任务的数据标注与外部训练**：在时频图上为左侧选中资产补齐检测标签，选好「训练集」「验证集」两个**信号集合**后启动仓库 `training/` 下的外部训练与验收流程，并在「实验与日志」里查看指标、加载验收通过的模型。它对应[00 技术方案](00电磁信号分析识别系统_Python技术方案.md) §4.7「AI 检测（可选，ONNX Runtime）」的训练侧：产物是 ONNX 模型与清单，由「信号检测」页（`per_hop_v1` 逐跳模型由「跳频参数」页）加载推理。

训练数据**直接取自信号集合的当前内容**：本页只做标注、配置、实验与日志，**不生成、不导出任何数据集，也不登记数据版本**。数据生成统一在「IQ 信号生成」页的「信号集合生成」子页完成（见[IQ 信号生成页面](02IQ信号生成页面.md)），人工修正标注在本页的「数据标注」子页完成，环境准备、命令行与操作步骤见[模型训练工作台](模型训练工作台.md)，集合／目标／标注的数据模型见[数据库设计](数据库设计.md)。

数据流向：左侧「信号集合」→ 训练集／验证集 → 运行目录 `training/runs/<时间-id>/collection_data/`（本次运行当时的内部输入快照）→ 外部训练与验收 → `model/` 下的 ONNX、清单与指标 → 点「加载验收通过的模型」写入「信号检测」页的 AI 入口。

## 1. 目标与边界

| 本页负责 | 本页不负责 |
| --- | --- |
| 检测标注：当前集合内左侧选中资产的框标注与无信号确认 | 生成或修改集合内容（「IQ 信号生成 → 信号集合生成」） |
| 训练配置：训练集／验证集集合、检测专属参数、启动前预检 | 导出训练集、创建/打开独立检测数据集、登记数据版本 |
| 外部训练进程的启动、进度、日志与取消 | 集合、标注集、类别字典的新建与归档 |
| 进程树收尾与窗口级运行槽的释放 | 数据资产与集合的浏览、迁移（「数据管理」页） |
| 历史实验浏览、指标展示、把验收模型加载到推理页 | 模型推理本身（「信号检测」/「跳频参数」页） |

三条硬约束：

1. **集合是唯一数据来源。** 训练集／验证集都必须是左侧存在且未归档的具体集合；页面没有数据集目录、数据来源字段，也没有「导出训练数据」入口。
2. **追加式版本，保存即生效。** 目标的参考参数与标签一律追加新版本，旧版本不修改、不删除；删框写的是 `include=False` 的负标注，而不是删除记录。
3. **保存即确认覆盖完整。** 「保存当前标注」表示整幅时频图已看过一遍：有框的目标记正样本，没有框的适用目标一律记为无信号，并把该资产在本次集合的覆盖度置为 `complete`；检测训练只纳入覆盖度 `complete` 的录制。

## 2. 页面入口与共享上下文

### 2.1 标签页位置与门禁

页面注册表顺序即界面顺序，共 11 页：信号导入 → IQ 信号生成 → 态势显示 → 信号检测 → 调制识别 → 跳频参数 → **信号检测训练** → AMC 识别训练 → 数据管理 → 算法对比 → 运行记录。所有跳页由页面注册表按下标驱动，改名或调序不会造成「静默跳到错误页面」。

- 本页固定任务为 `detection`，没有任务切换下拉；注册名（owner）与标题都是「信号检测训练」。
- 左侧「信号集合」处于**全部资产**或**零散资产**时，本页标签置灰不可进入；若当前正停在本页，先自动跳回「信号导入」再置灰（避免 Qt 把禁用页挪到相邻页）。选回具体集合后恢复可用。
- 标签置灰只是引导，不能替代校验：配置校验仍会独立拒绝缺失或非法的集合选择。

### 2.2 左栏共享上下文（信号集合）

两个训练页与其它页面共用同一个左侧面板；本页的标注对象与训练集默认值都来自它。

| 控件 | 行为 |
| --- | --- |
| 信号集合下拉 | 全部资产 / 零散资产 / 各集合（附资产数）。切集合前先保存训练页未保存的标注，保存失败会把下拉回滚到上次成功值并留在原地 |
| 按信号名称查找 | 对当前范围内的资产名称做搜索，与集合范围、标注过滤叠加 |
| 标注过滤器 | 全部 / 未标注检测信息 / 未标注AMC信息。口径是「资产有目标、但没有任何该任务的标签」；没有目标的资产（纯噪声负样本、已确认无信号）不进入结果，适用标记不参与过滤。过滤下推到数据层单条 `EXISTS`/`NOT EXISTS`，不做逐资产 N+1 查询，列表与计数共用同一条件；结果为空时给出明确空态 |
| 资产列表与分页 | 每页 100/200/500，显示「第 n/N 页」与「共 N 条 · 已过滤「…」」，上一页/下一页按边界启用 |
| 只读目标详情 | 每个目标一行：目标键、粒度（整条/会话/逐跳/片段）、检测与 AMC 适用标记、标注状态（检测已标注 / AMC已标注 / 待标注）、当前调制与版本来源；本页不在这里编辑 |

过滤只影响列表范围，不改变当前选中集合，也不触发训练集默认值变化。

### 2.3 跨页共享的运行槽

两页各持一个 `TrainingRunner`，共用窗口级的 `TrainingCoordinator`：**同一时间只允许一个训练运行**。占槽失败时第二次启动被拒绝、提示「「<占用页>」正在执行模型训练，请等待结束」，不创建实验目录、不产生第二个进程；另一页仍可编辑自己的配置、查看历史。运行槽只有在确认受管进程树已停止后释放，失败或强杀超时都保持占槽并可重试（详见 §6.5）。

两页各有独立 owner 与各自的横幅：进度、拒绝提示与「停止任务」都只出现在发起页，不会串页。

## 3. 「数据标注」子页

### 3.1 区块

| 区块 | 内容 |
| --- | --- |
| 标题栏 | 当前资产名 · 集合『<标注集名>』（<粒度>）；「保存当前标注」按钮 |
| 工具栏 | 新增信号框 / 删除选中框 / 标记无信号 / 启用检测标注 |
| 时频图 | 横轴为时间、纵轴频率递减（图像数组按「行 = 时间、列 = 频率」交给 row-major 的 `ImageItem`，写转置会旋转 90°）；单类 `emitter`；拖动框移动、拖角点缩放 |
| 状态栏 | 框数、适用目标数、待标注数、已确认无信号数、是否已保存；保存结果的摘要与提示 |

### 3.2 时频图现算与框往返

渲染不使用任何预先生成的图像文件：对左侧选中资产用 `spectral_context` + `detection_image` **现算**时频图，`nfft` 固定为 512，图像边长取「训练配置」里的**「时频图边长（检测）」**（128/256/512/1024，默认 1024），动态范围 60 dB。

框与物理量之间按项目唯一的映射往返：

- 读：目标的参考参数版本 → `band_to_box` → 归一化框；
- 写：框中心与尺寸 → `box_to_band` → 频率上下限与时间范围（再换算成采样点区间）。

目标的参考参数缺少频率上下限时不画框；保存时也要重新做一次往返，所以「框 ↔ 频率上下限/采样点」始终是同一份实现，标注与训练输入不会出现两套几何。

### 3.3 哪些目标需要标注

适用目标由当前集合检测标注集的 `label_semantics` 与目标粒度共同决定（`detection_label_applies`）：

| 粒度 | 规则 |
| --- | --- |
| `session_v1` | 标会话/整条/片段目标；逐跳子目标不要求标签 |
| `per_hop_v1` | 跳频会话的每个跳子目标要标；跳频父会话不要求；非跳频会话仍是一个框 |

跳频的父／子目标不会重复出现在同一份待标注清单里。资产的检测适用标记为 0 的目标不在列表内；页面会提示「（N 个目标未标记为适用检测，可点「启用检测标注」）」。

### 3.4 保存：追加式落库与覆盖完整

点「保存当前标注」后按下列顺序写入（全部走追加式版本）：

1. **有框的目标**：先 `append_target_version`（`source="manual"`，写时间范围与频率上下限），再 `append_detection_label`（`source="manual"`，绑定该参数版本，`include=True`）。
2. **新建框**：先 `add_target`（`scope="segment"`，目标键 `m1`、`m2`… 由页面在同一资产内保证唯一），再写参数版本与标签。
3. **没有框的适用目标**：写 `include=False` 的负标注（以库里的目标为准，而不是渲染时的快照——同一次会话中「新增后再删除」的目标也会留下负版本）；从未标注过的目标在这里一并确认为「无信号」，否则它们会让整条资产进不了训练。
4. **覆盖度**：最后写 `set_asset_coverage(task_set, asset, "complete", negative_kind=None, source="manual")`。

两条补充规则：

- **未编辑字段沿用上一版本。** 参数版本是**完整快照**，页面只编辑时间与频率，因此 SNR、调制、跳频标记、波形模式、符号率、名义带宽、功率、`params_json` 等由 `carryover_fields` 从上一版本带过来，不会被写成 NULL（`params_json` 在库里是 JSON 文本，协助函数会解码回对象，避免二次转义）。
- **缺少参考参数版本的目标会被训练排除。** 这类目标跳过不写，保存摘要里提示「N 个适用目标没有参考参数版本，训练仍会排除它们」，不做隐式补参数。

保存成功后刷新左栏目标详情（选择、状态与覆盖度同步更新）。

### 3.5 「标记无信号」「启用检测标注」与缺标注集

- **标记无信号**：清空所有框后按 §3.4 保存，但覆盖度带 `negative_kind="no_signal"`；整条资产作为负样本行进入训练（与 `build_rows` 的负样本口径一致）。
- **启用检测标注**：把该资产尚未适用检测的目标批量置 `for_detection=1`（对应「信号导入」只写 AMC 标签的资产），是显式动作，不做隐式改写；之后再画框保存。
- **缺标注集**：当前集合没有检测标注集时，页面只提示「集合「<名>」没有检测标注集：请到“IQ 信号生成 → 信号集合生成”勾选该任务的标注后重新生成，或先用该任务的训练页补标注」，**不自动创建标注集**。

### 3.6 切换、冻结与关窗

- 切换资产、切换左侧集合、开始训练、关闭窗口之前都会先保存未保存的编辑；**保存失败则回滚选择并留在原地**（资产按 ID 重新选中；原资产已不在列表中时给出明确提示），不静默丢弃修改。
- 集合刷新、侧栏集合下拉变化都走同一个守卫入口：先保存，失败则保留现有视图与上次成功的集合范围。
- 本页运行期间冻结配置输入与标注编辑（横幅、日志与取消仍可用）；另一页可编辑自己的配置、查看历史，但不能启动占槽操作。

### 4.1 字段

| 字段 | 说明 |
| --- | --- |
| 训练源码根目录 | 含 `training/desktop_worker.py` 的仓库根；默认取当前安装位置 |
| 训练环境 Python | 训练环境解释器（冻结应用不能把自身当 Python） |
| 模型 | `rtdetr` 与 `yolo26s`；发行版（冻结或 `SIMUSIGNAL_RELEASE=1`）只提供 `rtdetr` |
| 训练集（信号集合） | 只列未归档集合（附资产数）；默认跟随左侧当前集合，页内可改选，两页各自保存；页内改选后保留，直到侧栏再次切换集合 |
| 验证集（信号集合） | 独立选择，**默认不预设**（必须显式选择，避免与训练集悄悄相同） |
| 训练设备 / 轮数 / 批大小 / 学习率 / 随机种子 | 默认 cpu / 20 / 8 / 0.001 / 7；设备可选 cpu 或 cuda |
| 初始权重 | YOLO 空值使用 `yolo26s.pt`；RT-DETR 可指定初始 `.pth` |
| RT-DETR 配置 | 「rtdetrv2_pytorch 目录」与「RT-DETRv2 模型 YAML」，仅模型为 `rtdetr` 时显示 |
| 时频图边长（检测） | 128/256/512/1024，默认 1024；**同时用于标注渲染与训练输入** |

页内固定说明：「训练数据直接取自信号集合：选择训练集与验证集集合即可，页内不生成数据、不导出训练集。训练依赖安装在所选 Python 环境。」启动按钮为「开始训练 → 验收」，只有运行槽空闲、无独占冲突、两页都未在跑、且训练集与验证集都已选择时才可用。集合下拉框下方显示**输入提示行**（训练集/验证集各能提供多少可训练样本；AMC 页还会列出被跳过的标签状态），见 [AMC 识别训练](08AMC识别训练.md) §4.1。

### 4.2 预检清单

启动前逐条校验，任一失败都不占槽、不创建实验目录，错误同时显示在配置页红字与实验页状态。校验顺序与拒绝对应关系：

| 检查 | 拒绝文案 |
| --- | --- |
| 任务与模型 | 「信号检测训练 只接受 detection 训练任务」；「请选择当前页面支持的模型」 |
| 发行版模型门禁 | 「发行配置不提供 YOLO26s 训练」 |
| RT-DETR 路径 | 「RT-DETR 需要选择 rtdetrv2_pytorch 目录和模型 YAML」（校验 `<目录>/src/core/yaml_config.py` 与 YAML 文件存在） |
| 训练 Python / worker | 「请选择有效的训练 Python 和包含 training/desktop_worker.py 的源码目录」 |
| 集合选择 | 「请选择训练集和验证集信号集合」；「训练集与验证集不能是同一个集合」 |
| 集合存在与标注集 | 集合不存在时直接报错；缺标注集时报「集合「<名>」没有检测标注集：请到…勾选后重新生成…」 |
| 检测粒度一致 | 「训练集与验证集的检测标签粒度不同（会话级／逐跳级）：请在“信号集合生成”里统一粒度后重新生成」 |
| 类别字典一致 | 「训练集与验证集的类别字典不同，无法一起训练：请统一后重试」 |
| 可训练样本 | 「训练集／验证集没有可训练样本：N 条录制被排除（<资产名>：<原因>）。请先完成标注并确认覆盖度为 complete」；没有排除项时提示「…请在集合内完成检测标注后重试」 |
| 防泄漏 | 「训练集与验证集有 N 组同源数据（同一次采集或同一生成场景），会造成数据泄漏：请调整集合成员，把同源信号放在同一个集合里」 |

集合级预检由 GUI 与 worker 首阶段**共用同一个函数**，因此「预检通过」与「实际训练输入」始终是同一份装配结果。RT-DETR 路径与权重字段在模型切换时只调整可见性，不隐藏权重入口。

## 5. 训练数据流（集合 → 运行目录）

### 5.1 链路

1. GUI 组装的配置带 `train_collection_id` / `val_collection_id`（不再有数据集路径、来源、旧集合字段），另有 `workspace`、`task`、`arch`、`device`、`epochs`、`batch`、`lr`、`seed`、`image_size`、`nfft`，检测的权重与 RT-DETR 字段也原样落盘。
2. worker 首阶段「构建训练输入」：调 `inputs_plan` 复算一遍预检，取两个集合的检测标注集，用 `build_rows` 装配候选行（沿用适用目标、覆盖度与负样本口径），把训练集的行标 `split=train`、验证集的行标 `split=val`（**不调用按比例划分、不产生 `test` 划分**）。
3. 同一份行由 `detection_snapshot` 实体化到 `runs/<id>/collection_data/`：逐资产现算时频图存 `images/NNNNNN.npy`，框经 `band_to_box` 归一化，`annotation_status="reviewed"`，契约 `tf_image_v1`，并把训练集的 `label_semantics` 写进数据卡片；缺少频率上下限的目标不写框并计入 `skipped.missing_band`。
4. 后续阶段不变：检测沿用 `AnnotationDataset(data).snapshot(output/"data")` 与现有训练／验收脚本；`test` 不参与模型选择。
5. 溯源分两处：`experiment.json` 的 `config` 保存两个集合 ID（页面配置原样落盘）；运行目录内另写 `training_inputs.json` = `plan_summary(plan)`，记录两个集合的 ID／名称、标注集 ID 与启动时的样本统计（样本数、正样本、负样本、资产数）。**不写 `dataset_version_id`**。

### 5.2 运行目录布局

| 路径 | 写入者 | 内容 |
| --- | --- | --- |
| `runs/<id>/experiment.json` | GUI 运行器（worker 只读） | 运行记录：配置、状态、阶段、指标事件、错误、PID |
| `runs/<id>/environment.json` | worker | Python 与已装包版本（torch / torchvision / onnx / onnxruntime / ultralytics / torchsig） |
| `runs/<id>/worker.log` | 运行器按原始字节追加 | 合并 stdout/stderr；实验页只读末尾约 200 KB |
| `runs/<id>/training_inputs.json` | worker | 两个集合的溯源与启动时样本统计 |
| `runs/<id>/collection_data/` | worker（本次输入快照） | 检测：`AnnotationDataset`（`images/`、`dataset.json`、`samples.jsonl`） |
| `runs/<id>/data/`、`native_data/`、`native_run/` | worker | 检测侧的契约快照、原生数据集与上游训练目录 |
| `runs/<id>/model/` | worker | ONNX（`detector.onnx`、原生 `native.onnx`）、`detector.json` 清单、`metrics.json` |
| `runs/<id>/native_parity.json`、`verification.json` | worker | 原生/契约模型数值对账、模型契约验收报告 |

`collection_data/` 只是喂给训练脚本的内部快照，**不作为用户可见的「导出的训练集」**，也不在 `datasets/` 或数据版本表登记。

### 5.3 可复现性声明

训练输入取自集合的**当前**内容：集合成员、目标参数或标签在实验之后变化，历史实验**不保证**逐位复现，也不会自动重跑或回滚；`collection_data/` 是本次运行当时的快照，可用于复核该次实验用到的样本，但不构成版本化数据资产。严格复现（数据版本 + 不可变清单 + 实验绑定版本）是另一条独立路线，本页不做。

## 6. 运行、进度与收尾

### 6.1 启动

1. 保存未保存的标注；构造配置快照；协调器尝试占槽（失败只提示，不创建目录）。
2. 校验配置、Python 与 worker；失败释放槽、不创建实验记录。
3. 登记为外部任务（`kind="external"`，横幅、取消与清理/迁移独占规则纳入统一任务体系），成功后创建运行目录与 `experiment.json`，再用 bootstrap 启动 `training/desktop_worker.py`；环境变量强制 `PYTHONUNBUFFERED`、`PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1`，并限制线程数为 2。
4. 进程启动后把根进程挂到受管进程树并写入 PID；任何一步异常都进入统一收尾：刷新尾部输出、清理受管进程树、写最终记录（能写则 `failed`）、清理句柄、释放槽、重算两页控件。

### 6.2 进度事件

worker 向标准输出打印 `TRAIN_EVENT <JSON>`（UTF-8、立即 flush），运行器逐行解析并把事件归一化成任务横幅的 `done/total`：

| 事件 | 载荷 | 归一化 |
| --- | --- | --- |
| 阶段事件 | `{"stage": …, "message": …, "done": n, "total": m}`（带进度时）或只有 `{"stage": …}` | 状态栏显示 `stage`；显式覆盖 `done/total`，没有进度信息时用 `0/0` 表示忙碌态 |
| 轮次事件 | `{"epoch": n, "loss": x}`（AMC 侧另有 `validation_accuracy`） | `done=min(n, config["epochs"])`、`total=config["epochs"]`，文案「训练第 n/N 轮 · loss x」 |

两条语义必须一起看：

- **每次事件都显式写 `done/total`**，所以**换阶段会清零**，横幅不会停在上一阶段的进度（例如快照阶段的 2/2）。
- **轮次事件只带 `epoch`**，总量取自运行配置，没有倍率信息时退化为忙碌态。

检测侧首阶段的阶段事件由集合快照进度上报（「构建训练输入」→「渲染检测样本 i/N」→「训练输入就绪：N 个样本」），随后是「校验标注并保存数据快照」、RT-DETR（或 YOLO26s）训练与原生导出、数值对账、按标注框评估、模型契约验收；轮次事件来自上游训练回调。

### 6.3 日志与曲线

- 日志以原始字节追加写入 `worker.log`，实验页读取末尾片段后用**先 UTF-8、再 GBK、最后替换**的顺序解码：新实验是 UTF-8，历史实验可能由管道默认编码（GBK）写出。
- 曲线：loss 由轮次事件的 `loss` 绘制；第二条曲线为验证准确率（AMC 页使用，检测页为空）。
- 阶段文案、日志与曲线都只反映本次运行；运行结束或收尾后按钮恢复。

### 6.4 实验目录内容

`experiment.json`（含配置/状态/阶段/指标/错误）、`environment.json`、`worker.log`、`training_inputs.json`、`collection_data/`、`data/`、原生数据集与训练目录、`model/` 下的 ONNX 与清单与 `metrics.json`、`native_parity.json` 与 `verification.json`。实验记录原子写入（先写 `.tmp` 再替换）；日志或记录写入失败会显示错误、但仍会执行进程树收尾，不伪称「已保存」。

### 6.5 取消、关窗与进程树

- **取消**：点横幅取消或实验页「停止任务」都取消同一个任务 ID。运行器先请求受管进程树停止（POSIX 向进程组发 SIGTERM；Windows 终止根进程并依赖 Job Object），**等待 2 秒**仍未退出则强制结束（POSIX SIGKILL 进程组；Windows `TerminateJobObject` 并对未进入 Job 的后代逐个终止）。取消请求只表示「正在取消」，不立即清槽、不改实验终态；已被取消的任务按 `cancelled` → 实验记录 `stopped` 落盘。
- **进程树监管**在训练子进程创建前建立：Windows 用 Job Object（句柄关闭即终止的限额）+ 启动门事件（子进程先等 Job 赋值成功再运行）+ 枚举 worker 后代并持有句柄，覆盖「宿主环境不继承嵌套 Job」的情况；若当前作业环境不支持「句柄关闭时自动终止」，会在日志给出警告并退化为显式终止整个进程树。POSIX 由 `desktop_worker.py` 建立新会话，停止即对进程组发信号。**只在一处 `setsid`**，避免第二次调用因进程已是会话首进程而失败。
- **只有确认受管进程树为零才释放槽**：worker 根进程退出不等于任务结束。收尾轮询无法确认时会保持占槽、提示错误并重试强制停止，不调用结束后置、也不允许新实验。根进程崩溃但有子进程、启动后立即取消、正常退出仍留子进程三种场景都由同一路径收尾；如果 worker 退出时仍有子进程，记录会追加「训练 worker 退出时仍有子进程；已终止残留进程」并判为失败。
- **关窗**：先调用检测页的保存钩子，失败则阻止关闭（不先去停另一页任务）；保存通过后遍历两个运行器，TERM 等 1 秒、强制结束再等 1 秒，任一仍未退出则忽略关闭事件，允许重试。运行期间页面由窗口持有，不单独销毁。
- **幂等**：重复的 `errorOccurred/finished`、重复停止、延迟的强杀定时器都带运行 ID，只能作用于同一实验，不会终止随后启动的新实验。

### 6.6 失败与重跑

预检失败、任务登记被拒、`FailedToStart`、崩溃、日志/记录写盘失败都进入统一收尾：**运行槽不永久占用**，列表与控件恢复可用，已有记录尽量写为失败并保留原因，可再次启动。历史记录只在展示副本上按 PID 探活改判「已中断」，不写回磁盘、也不接管旧进程。

## 8. 操作流程

1. 在「IQ 信号生成 → 信号集合生成」批量生成并自动标注（默认逐跳粒度），或用「信号导入」导入录制后加入集合；确保集合勾选了检测标注。
2. 左栏选中该集合；用「未标注检测信息」过滤或按信号名称查找需要补标注的资产。
3. 切到「信号检测训练 → 数据标注」：核对时频图，画框/改框/删框；确认真没有信号时用「标记无信号」；只写了 AMC 标签的资产先点「启用检测标注」再画框；点「保存当前标注」（保存同时确认覆盖度 `complete`）。
4. 切到「训练配置」：填训练源码根目录与训练 Python，选模型（RT-DETR 另选目录与 YAML）、训练集（默认跟随左侧集合）与验证集（显式选择、与训练集不同且不同源）、设备/轮数/批大小/学习率/种子，确认「时频图边长（检测）」。
5. 点「开始训练 → 验收」：通过预检后自动切到「实验与日志」，观察阶段、日志、loss；需要中断时点横幅取消或「停止任务」。
6. 结束后在「实验与日志」核对指标；确认可用后点「加载验收通过的模型」，到「信号检测」页（逐跳模型到「跳频参数」页）对所选资产执行 AI 检测。

## 9. 常见问题（FAQ）

- **为什么没有「导出训练数据」按钮？** 训练运行自己从集合取输入：worker 首阶段把训练集/验证集实体化成运行目录里的 `collection_data/`。页面既没有数据集目录字段，也没有导出任务；旧的导出入口与旧 `asset`（资产转样本）任务都已删除，仅历史记录仍可见。
- **训练集／验证集怎么选？为什么验证集默认空？** 训练集默认跟随左侧当前集合（页内可改选，两页各自保存）；验证集必须显式选择——默认留空是为了避免它与训练集悄悄相同。
- **保存标注后，为什么没画框的目标变成了无信号？** 「保存当前标注」等于声明「整幅时频图已看过一遍」：没有框的适用目标一律记 `include=False`，并把覆盖度置 `complete`。这样人工补标后的资产才能进入检测训练（训练只纳入覆盖度 `complete` 且适用目标都已标注的录制）。
- **「标记无信号」和「保存当前标注」有什么区别？** 前者清空所有框后保存，并把覆盖度记为 `negative_kind=no_signal`（整条资产是负样本）；后者按当前框图保存，不写 `negative_kind`。
- **框和频率范围怎么换算？** 框 ↔ 频率上下限/时间范围用项目唯一的 `band_to_box` / `box_to_band` 往返，标注与训练输入共用，不存在第二套几何。
- **为什么某个资产进不了训练？** 常见原因：覆盖度不是 `complete`（没保存过标注）、有适用目标缺标签或缺参考参数版本、检测适用标记为 0。预检会把被排除的录制与原因列出来。
- **两个集合「同源」是什么意思？** 资产带有同一个 `origin_group_id`（同一次采集或同一生成场景）。它同时出现在训练集与验证集会数据泄漏，预检直接拒绝并列出冲突组。
- **训练进度为什么会在换阶段时重新开始？** 阶段事件与轮次事件每次都显式写 `done/total`，换阶段清零是刻意行为，避免横幅停在上一阶段；轮次事件的总量取自配置里的轮数。
- **取消训练要多久？** 先请求进程树停止并等 2 秒，未退出才强制结束；只要进程树未确认退出就保持占槽并可重试。关窗路径是 TERM 等 1 秒、强杀再等 1 秒。
- **为什么实验页通常只有验证集？** 训练输入不产生 `test` 划分：训练集行 → `train`、验证集行 → `val`。测试集不参与模型选择，本页不做自动留出。
- **「加载验收通过的模型」为什么是灰的？** 只有记录状态为成功、对应清单存在、且任务属于本页时才可用；失败/取消/中断、`asset` 记录以及发行版隐藏的模型都不可加载。
- **发行版为什么没有 YOLO26s？** YOLO26s（Ultralytics）按 AGPL-3.0 处理，只作内网开发对照：冻结构建与 `SIMUSIGNAL_RELEASE=1` 时隐藏该入口，配置校验也拒绝它。
- **训练数据能复现吗？** 不承诺：输入取自集合的当前内容，集合后续变化不会让历史实验回滚或重跑。同一次运行可用运行目录里的快照复核。
- **日志出现乱码？** 新实验按 UTF-8 写出；历史记录由管道默认编码（GBK）写出，读取时按 UTF-8 → GBK → 替换逐级回退。

## 11. 已知局限与后续方向

- **实采跳频的逐跳人工标注未实现。** 目前只有生成器写出的逐跳目标能用于 `per_hop_v1` 训练；实采录制只能先做会话级标注（`session_v1`），逐跳标注（在会话框内按跳加框、用跳速/驻留/频点表辅助切分）是后续方向。
- **不保证跨运行复现。** 集合内容变化后历史实验不自动重跑或回滚；如需严格复现，需要另行引入数据版本与不可变清单。
- **发行版不提供 YOLO26s**，只保留 RT-DETR；YOLO26s 仅作内网开发对照。
- **未做真实显示器上的人工布局与交互验收**（GUI 流程由离屏集成测试覆盖），RT-DETR 的 CUDA 与冻结发行包需在目标环境另行验收；该桥不支持 Paddle 与 PyTorch v1。
- **首阶段取消为终止进程树**（不轮询取消标志），已写入的输入快照会保留半成品目录，便于复核，不视为有效实验。
- 尚无多实验 A/B 汇总界面；检测指标是二维框评分，不等同于生成器业务频段评分；验收通过只表示链路正确，不代表精度达标。
