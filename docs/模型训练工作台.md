# 模型训练工作台

桌面「模型训练」页包含「数据标注」「训练配置」「实验与日志」。训练在外部 Python
进程中运行，GUI 不导入 PyTorch。

## 手工标注

1. 在左侧通过「导入 IQ / SigMF」导入数据，或用「IQ 信号生成」创建资产。
2. 在训练配置中选择新建图像边长，然后到「数据标注」点击「新建标注集」。默认 1024。
3. 在左侧选择资产，点击「添加左侧选中 IQ 资产」。后台将每个资产转换为一张时频图。
4. 点击「新增信号框」，拖动框移动、拖动角点缩放；点击框后可删除。
   横轴为时间，纵轴向下频率递减，顶部为最高频率。
5. 选择训练集或验证集，保存标注。无信号数据点击「标记无信号」后保存。
   未确认样本会阻止训练，避免被误当作负样本。
6. 至少准备一个训练样本和一个验证样本；正式训练需要更多独立录制样本。

第一版固定单类 `emitter`，新建数据集采用会话级标签。可打开生成器或 TorchSig
转换的检测数据集修正标签；已有逐跳数据集会保留其标签语义。
同一资产不能重复添加，同源窗口应放在同一划分，避免数据泄漏。

修改保存到 `annotations.json`，原始 `samples.jsonl` 保留。切换样本或正常关闭窗口时
保存尚未保存的编辑。训练启动后复制图像和合并后的标签作为本次快照，后续标注不会影响本次实验。

## 配置训练环境

页面中选择包含 `training/desktop_worker.py` 的源码根目录和训练 Python 解释器。
冻结应用不能把自身当作 Python；需选择独立环境。训练源码不随 wheel 交付。

```bash
python3 -m venv .venv-training
.venv-training/bin/python -m pip install -e '.[train,ml]'
# YOLO26s 开发对照需要：
.venv-training/bin/python -m pip install ultralytics
```

### 检测模型

- **YOLO26s**：选择本地初始权重，或留空使用 `yolo26s.pt`（首次可能下载）。
  复用 Ultralytics 训练器，关闭翻转、旋转、拼图等破坏时频图含义的增强。
  按已授权的开发对照策略自动传递放行参数，清单保持 `distributable: false`。
- **RT-DETR**：选择官方 [lyuwenyu/RT-DETR](https://github.com/lyuwenyu/RT-DETR)
  的 `rtdetrv2_pytorch` 目录和具体模型 YAML，例如
  `configs/rtdetrv2/rtdetrv2_r18vd_120e_coco.yml`。安装该实现需要的
  PyYAML、scipy、faster-coco-eval、pycocotools、tensorboard 等依赖。
  可指定初始 `.pth`。入口生成本次实验专属 YAML，配置数据、单类字典、尺寸、轮数、
  批大小及学习率；其他策略仍由原 YAML 决定，包括骨干预训练权重下载。
  当前桥不支持 Paddle 或 PyTorch v1。

### IQ 分类

选择 CNN / TCN。可以使用已有 `iq_dataset.json` / `iq_dataset.npz`，或在页面生成 A09 数据。
混入 TorchSig bundle 必须提供显式 JSON 映射；生成配置的映射目标限定为
`fm, ssb, ask2, qpsk, qam16, qam64`。已有自定义类别数据集仍可训练。
CUDA 可用性在所选 Python 环境中检查。

### 生成数据

配置页提供本项目生成器和 TorchSig 准备检测数据的按钮，完成后自动打开标注页面。
`.[train]` 已包含固定版本 TorchSig 2.2.0；只需要数据生成时也可安装 `.[torchsig]`。
已有 bundle 的转换和混入不需要安装 TorchSig。
建议先小规模生成，空间与机时需求取决于实际规模。

## 训练、评估、加载

点击「开始训练 → 导出 → 验收」。实验页显示阶段、日志、loss 和 IQ 验证准确率。
停止或正常关闭窗口会结束训练进程组；第一版不支持断点续训。重启后可查看历史日志和指标。

检测导出先做原生图与契约图的独立数值对账，再运行 `verify_onnx.py`。
这两个原生导出入口接收 RGB float32 `[0,1]`，工作台明确传递 `input_scale=1`，
不沿用通用适配器的历史默认缩放。

检测指标按保存的标注框计算：置信度 0.25、NMS IoU 0.5、匹配 IoU 0.5。
报告包括精确率、召回率、无信号样本误报率、CPU 推理与去重 P50/P95；延迟不包含 IQ 转图。
测试集不参与模型选择，训练结束后单独评估。这是二维框评分，不等同于生成器业务频段评分。

IQ 验证准确率和混淆矩阵使用数据集标签，不依赖资产 `generation`。
识别页面的当前资产真值评分仍受资产真值及类别映射限制，两者不会混用。
验收通过后点击「加载验收通过的模型」，清单会填入检测或识别页面。
验收通过只表示链路正确，不代表模型精度已达到应用要求。

## 文件与当前边界

所有数据默认保存在工作区的 `training/datasets/` 和 `training/runs/<时间-id>/`。
每个实验保存 `experiment.json`、`environment.json`、`worker.log`、数据快照、
原生训练权重、`model/` 下的 ONNX/清单/指标，以及 `verification.json`。

- 标注器支持本项目时频图格式，不接受任意截图；不提供 IQ 调制类别人工编辑。
- 两个检测后端共用评估口径，尚无专门的多实验 A/B 汇总界面。
- TorchSig 2.2.0 的真实 CPU 生成与 GUI 导入已验证；CUDA 和最终冻结发行包需在目标环境另行验收。
- 冻结构建排除 torch、torchvision、ultralytics、torchsig；冻结应用或
  `SIMUSIGNAL_RELEASE=1` 时隐藏 YOLO26s 入口。训练源码、权重和实验目录不随 wheel 交付。
