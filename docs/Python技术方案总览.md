用户新增要求见[核心模块二进制化与原生插件接口方案](核心模块二进制化与原生插件接口方案.md)：两项目预留核心源码编译边界；电磁信号分析识别项目增加用户 DLL/SO 接入和 SDK 交付。[通用调用示例](../examples/native_plugin/README.md)已提供，可验证 C 动态库与 Python 的互操作。

本轮依据两份 Word 的正文和表格制定方案，没有将其中的示意图、公式图片及代码截图视为已复核的实现。方案针对通用离线实验和软件工程，不展开专用军事通信协议、跳频图案、抗干扰设计或实装侦察优化。

全文标注规则：**原文要求**来自需求材料；**设计建议**为本方案的工程选择；**待确认**表示原文不足以确定，不能作为已经承诺或达到的验收指标。

## 2. 共用与独立部分

| 领域 | 可共用部分 | 应独立部分 |
| --- | --- | --- |
| 桌面界面 | 主题、导航、任务进度、日志、文件选择 | 信号分析工作台、仿真场景工作台 |
| 数据 | 文件资产、校验摘要、元数据版本、实验记录 | 识别结果及题库、仿真事件及模型配置 |
| 任务 | 进程管理、取消、错误处理、结果提交 | 分析任务执行器、仿真执行器 |
| 可视化 | 图表容器、导出、单位格式、时间轴组件 | 波形视图、仿真拓扑与事件回放 |
| 验证 | 测试框架、基准报告、环境清单 | 数据集评估、仿真参考模型一致性 |
| 交付 | 离线依赖包、构建脚本、版本和许可清单 | 两个安装包、两套用户手册和验收材料 |

共用库只维护稳定的软件基础能力；避免把两个项目的业务表、实验配置和模型假设绑定在一起。初期采用单仓库、独立 Python 包和独立发布入口，具备明确需求后再决定是否拆仓库。

以下目录已实际落地。两个业务拥有独立包、命令行、桌面入口、测试及发布清单；`common` 不导入业务包。逐文件映射见实现说明：

```text

  analysis_desktop/    # main.py、独立 pyproject.toml、项目说明

  analysis/
  simulation/
benchmarks/           # 两项目独立基础流程基准
packaging/            # projects.json：两个独立打包目标
docs/
```

## 3. 推荐技术栈

| 层次 | 设计建议 | 选择理由及条件 |
| --- | --- | --- |
| 语言 | CPython；具体小版本在兼容性验证后锁定 | 先验证目标麒麟系统与处理器的二进制依赖，再冻结版本 |
| 桌面界面 | PySide6 / Qt Widgets | 两项目均可采用本地桌面交互；跨平台仍须逐平台测试 |
| 交互图形 | PyQtGraph | 适合科学数据的交互图表 |
| 数值计算 | NumPy、SciPy | 统一数组表示及通用科学计算 |
| 仿真调度 | SimPy | 适合进程式离散事件仿真，不提供波形模型正确性保证 |
| 元数据 | Python sqlite3；版本化 SQL 迁移 | 单机部署轻便，原始大文件另行保存 |
| 大数组 | 原始二进制 / NPY + 分块读取 | 限制驻留内存；HDF5 仅在复杂层次数据确有需要时引入 |
| 模型运行 | 已验证模型适配器；ONNX Runtime 为候选 | 需验证模型算子、目标 CPU 架构和运行后端 |
| 核心编译 | Cython 编译自研核心为 `.pyd` / Python 扩展 `.so` | 与 CPython、系统及 CPU 兼容；开发阶段建立双模式回归 |
| 用户原生插件 | 独立工作进程 + ctypes + 版本化 C ABI | DLL/SO 按平台构建，提供头文件、依赖和参考结果 |
| 静态报告 | HTML、CSV、PNG；按交付要求增加 PDF | 与交互界面分离，便于归档和审阅 |
| 工程检查 | pytest、代码静态检查、依赖锁定、构建脚本 | 保证软件行为和交付环境可重复 |
| 打包 | PyInstaller 的平台独立构建产物 | 优先目录式离线分发，分别生成 Windows 和麒麟包 |

PySide6 是 Qt 的 Python 绑定；PyQtGraph 面向科学图形；NumPy 的内存映射支持访问大文件片段；SimPy 是离散事件框架。这些是工具能力依据，表中的组合方式是本方案的工程判断。[Qt for Python](https://doc.qt.io/qtforpython-6)、[PyQtGraph](https://pyqtgraph.readthedocs.io/en/latest/)、[NumPy memmap](https://numpy.org/doc/stable/reference/generated/numpy.memmap.html)、[SimPy](https://simpy.readthedocs.io/en/stable/index.html)。

ONNX Runtime 的后端支持取决于安装包和平台；PyInstaller 不是跨平台交叉编译器。[ONNX Runtime 后端](https://onnxruntime.ai/docs/execution-providers/)、[PyInstaller 官方手册](https://www.pyinstaller.org/en/stable/)。

## 4. 应优先关闭的需求缺口

| 优先级 | 问题 | 对实施的影响 | 关闭依据 |
| --- | --- | --- | --- |
| P0 | 麒麟版本、CPU 架构、显卡和驱动未锁定 | 安装包、界面、数值库、模型运行存在不同适配成本 | 目标机器清单及可使用的测试机 |
| P0 | 实际信号文件格式和可用样本未知 | 导入和模型评估不能形成可信闭环 | 格式说明、元数据、独立参考样本 |
| P0 | 某星专用协议及 SDPSK 定义缺失 | 无法判断模型是否与目标系统一致 | 版本化模型规范和参考输入输出 |
| P0 | “1 GHz”带宽与“0～1 GHz”范围的关系不明确 | 决定仿真层级、数据量、硬件和工期 | 频率坐标、采样表示及实时性口径 |
| P0 | 识别准确率、估计误差、处理时延没有合格门限 | 能输出结果不等于性能通过 | 固定数据集、统计方法、门限和硬件 |
| P0 | 识别项目相对工期与绝对交期需核对 | 若从当前日期新启动，原 150 日计划无法照搬 | 合同签订日、既有成果、第三方测试排期 |
| P1 | 两项目是否需要互导数据 | 决定交换格式和真值隔离策略 | 数据交换用例及验收样例 |
| P1 | 某星项目操作系统和交付日未说明 | 无法套用另一项目的平台与进度承诺 | 独立交付基线 |
| P0 | 用户动态库的 ABI、架构、依赖及样例未知 | 无法承诺任意 DLL/SO 直接加载 | 头文件、调用说明、库文件及参考数据 |
| P1 | 核心源码编译与源码包的交付方式 | 决定运行包内容及重建材料 | 保留合同源码交付，确认是否另附于运行包 |

建议先完成一次范围有限的可行性验证：在目标机启动界面、读取代表性大文件、运行现有模型样例、完成一个抽象仿真任务并导出报告。输出实测数据和缺口清单后再冻结开发计划。

## 5. 交付与验收原则

每个项目分别维护“需求编号 → 软件模块 → 测试用例 → 结果证据”的追踪表。测试报告应包含数据版本、配置摘要、模型版本、依赖版本、硬件、耗时和失败样本，不能仅交付界面截图。

当前已实现两个独立桌面应用与 CLI，包含通用数值算法、资产管理、信号 IQ 生成（测试信号源）、消息队列演示、原生复制插件接入、数值核心编译及自动化测试。分析默认使用 `workspace_data/analysis`，仿真默认使用 `workspace_data/simulation`；两个目录有项目标识，不能交叉打开。每个 wheel 和桌面产物只包含本项目业务代码与共用基础库。正式算法 SDK、专用模型、设备适配及原始项目性能指标仍待实现或验证；具体范围以[基础工程实现说明](基础工程实现与文件说明.md)为准。
